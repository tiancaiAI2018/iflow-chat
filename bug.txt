# Bug: 流式消息结束后内容消失

## 问题
用户发送消息后，AI 流式回复正常显示，但回复结束后消息气泡消失，内容看不见。

## 原因

### 后端 (backend/routers/websocket.py)
- `if msg.content:` 过滤了空内容的完成消息
- 前端收不到 `is_finished=true` 的标志
- `TASK_FINISH` 类型消息未发送给前端

### 前端 (frontend/src/hooks/useWebSocket.ts)
- React 闭包问题：`currentAssistantMessage` 在 `setMessages` 中是旧值
- 空内容的非 delta 消息会覆盖已累积的流式内容

## 修复

### 后端
```python
# websocket.py - 始终发送消息，包括空内容的完成消息
await websocket.send_json(
    AssistantMessageResponse(
        content=msg.content,
        is_delta=msg.is_delta,
        is_finished=msg.is_finished,
    ).model_dump()
)
```

### 前端
```typescript
// useWebSocket.ts - 使用 ref 追踪累积内容，避免闭包问题
const streamingContentRef = useRef<string>('');

// 完成消息只作为结束信号，不覆盖累积内容
if (message.is_finished) {
  const finalContent = streamingContentRef.current;
  // 添加到消息列表...
}
```

## 排查方法
1. 检查后端日志，确认消息已发送
2. 检查浏览器 Network 面板，确认 WebSocket 消息
3. 在前端添加 console.log 追踪消息状态
4. 检查 React 闭包问题（state 在异步回调中的值）

# Bug: ToolCallMessage 属性名错误

## 问题
发送需要工具调用的消息（如"查看今日A股情况"）时，后端报错：
```
'ToolCallMessage' object has no attribute 'arguments'
```

## 原因
iflow-sdk 的 `ToolCallMessage` 类属性名是 `args`，不是 `arguments`。
代码中错误地使用了 `msg.arguments`。

## 修复
```python
# iflow_client.py - 使用 getattr 安全获取属性
tool_args = getattr(msg, 'args', None) or getattr(msg, 'arguments', None) or {}
```

## 排查方法
1. 查看后端日志中的具体错误信息
2. 检查 iflow-sdk 源码中的 ToolCallMessage 类定义
3. 使用 `grep -A 20 "class ToolCallMessage"` 查看属性列表

# Bug: 工具调用显示顺序错误和状态不更新

## 问题
1. 工具调用显示在 AI 回复的最后，而不是按实际调用顺序显示
2. 工具状态一直显示"等待中"，不会更新为"成功"或"失败"
3. Chat.tsx 没有传递 toolCall 属性给 Message 组件

## 原因

### 顺序问题
原设计将工具调用存储在 ref 中，等到消息结束时才添加到消息列表。

### 状态问题
iFlow SDK 只发送一次工具调用消息（状态是 `pending`），不发送后续状态更新。

### 前端问题
Chat.tsx 没有传递 `toolCall` 属性给 Message 组件，导致工具调用消息无法渲染。

## 修复

### 前端 - 工具调用作为独立消息
```typescript
// useWebSocket.ts - 工具调用立即作为独立消息添加
case 'tool_call':
  const newToolCall: ToolCall = {
    tool_id: message.tool_id,
    tool_name: message.tool_name || 'unknown',
    arguments: message.arguments || {},
    status: message.status || 'in_progress',
    result: message.result,
  };
  
  // 添加新的工具调用消息
  setMessages((prev) => [
    ...prev,
    {
      id: `tool-${Date.now()}-${toolKey}`,
      role: 'tool_call',
      content: '',
      toolCall: newToolCall,
      created_at: new Date().toISOString(),
    },
  ]);
```

### 前端 - 消息结束时更新工具状态
```typescript
// useWebSocket.ts - 消息结束时将所有工具调用标记为已完成
if (message.is_finished) {
  setMessages((prev) => 
    prev.map((msg) => {
      if (msg.role === 'tool_call' && msg.toolCall && msg.toolCall.status !== 'completed') {
        return {
          ...msg,
          toolCall: { ...msg.toolCall, status: 'completed' },
        };
      }
      return msg;
    })
  );
}
```

### 前端 - Chat.tsx 传递 toolCall 属性
```tsx
// Chat.tsx
<Message
  key={msg.id}
  id={msg.id}
  role={msg.role}
  content={msg.content}
  isStreaming={msg.isStreaming}
  toolCalls={msg.toolCalls}
  toolCall={msg.toolCall}  // 添加此行
  created_at={msg.created_at}
/>
```

### 后端 - 添加 tool_id 字段
```python
# iflow_client.py - 添加 tool_id 字段
tool_id = msg.id or f"{tool_name}-{hash(str(tool_args))}"

return ChatMessage(
    type=MessageType.TOOL_CALL,
    tool_id=tool_id,
    tool_name=tool_name,
    tool_arguments=tool_args,
    tool_status=status_map.get(msg.status, "in_progress"),
    tool_result=tool_result,
)
```

2. 检查 WebSocket 消息顺序
3. 检查 React 组件 props 是否正确传递
4. 检查 iFlow SDK 消息结构（ToolCallMessage 属性）
